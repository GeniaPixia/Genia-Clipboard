# GeniaClipboard 0.5.9 RC1 — сборка для Windows

Это **тестовая** версия; официальная 0.5.8 остаётся без изменений.

## Сборка из полного исходного ZIP

1. Распакуйте **весь** ZIP исходного проекта в новую пустую папку.
2. Запустите `build.cmd` двойным щелчком или из обычного `cmd.exe` (без прав администратора).
3. Сценарий проверит наличие .NET SDK, выполнит `dotnet restore` с **официальным** `https://api.nuget.org/v3/index.json`, затем `dotnet publish` для Windows x64.
4. После сообщения `RESULT=BUILD_PASS_EXE_NOT_EXECUTED` тестовый файл будет находиться в `TEST_PUBLISH\GeniaClipboard.exe` внутри исходного проекта. Сценарий **не запускает EXE автоматически**.
5. Проверьте EXE антивирусом и используйте для тестов только вымышленные записи. Не копируйте туда папку Data от официальной версии.

## Почему предыдущая сборка не прошла

В журнале использовался .NET SDK `11.0.100`. Проект нацелен на `net8.0-windows` и `RuntimeFrameworkVersion 8.0.30`. При восстановлении использовался только локальный каталог `C:\Program Files\dotnet\library-packs`, где не нашлось `Microsoft.NETCore.App.Ref`, `Microsoft.WindowsDesktop.App.Ref` и `Microsoft.AspNetCore.App.Ref`.

`build.cmd` явно указывает NuGet.org как источник пакетов **только для операции restore**. Требуется сетевой доступ к официальному источнику, если необходимые компоненты не установлены в системе. Не отключайте антивирус, SmartScreen или TLS-проверки. Если NuGet.org недоступен, пришлите полный вывод сборки для отдельной диагностики.

SDK 11 может собирать проект, предназначенный для .NET 8, если необходимые пакеты доступны. Принудительное изменение TargetFramework на .NET 11 **не требуется**.

## Предохранители

- Запрещено перезаписывать уже существующую `TEST_PUBLISH`: перед повторной сборкой переименуйте или переместите только тестовую папку.
- Никаких операций над существующими пользовательскими Vault, Data или установленным GeniaClipboard.
- Сценарий не меняет системные политики Windows, NuGet.Config, переменные окружения вне процесса или параметры Defender.
- В CI PowerShell GitHub Actions устанавливает `CI=true`, поэтому пауза в конце `build.cmd` не мешает автоматической проверке.
- Сам факт успешного построения не подтверждает отсутствие подмены после финальной проверки буфера и не заменяет ручные тесты C1–C9 из `docs/CLIPBOARD_INTEGRITY_QA.md`.
